# NW-A306 hardware evidence matrix

M0, 2026-10-13. **No subsystem is verified under custom firmware.** “Observed”
means preserved stock-device/host evidence; “Source” means code/configuration
exists in the reviewed release; “Hypothesis” is a candidate requiring proof.
All citation IDs resolve to the [feasibility evidence register](feasibility.md#evidence-register).

| Subsystem | Verified observation or source finding | Research hypothesis | Unknown / acceptance evidence needed |
| --- | --- | --- | --- |
| CPU / platform | Observed QCS2290, `bengal`, `icx1301` (D1). Source ARM64 Qualcomm config with `CONFIG_COMPAT` (S1). | Linux can reuse platform support; 32-bit userspace may reduce porting work. | Actual handoff state, memory map, reserved memory, usable ABI and complete kernel/toolchain build inputs. |
| Boot / verified boot | Observed locked state and `green` (D1); maintainer reports accessible fastboot and failed query (D2). | An authorized boot mechanism may exist; none established. | Device-specific unlock/acceptance policy, secure-loader stages, image formats, AVB/rollback data and supported recovery. **Blocking.** |
| Board description | No `icx1301` or Bengal DTS member names in full archive inventory; generic Qualcomm DT Makefile (S9). | Stock DTB/DTBO may supply board integration data. | Authentic board DT and selected overlays, GPIOs, rails, clocks and bindings. No DT recovered or modified in M0. |
| Display / backlight | DRM/backlight and Bengal DRM/SDE/DSI source configuration (S1/S9); Rockbox Linux framebuffer backend exists (R2). | Reuse vendor display driver, then adapt framebuffer or DRM output. | Actual panel, timing, reset/power sequence, pixel format/orientation, brightness range and `/dev/fb0` availability. Config presence is not a working screen. |
| Touchscreen | Published config selects Himax HX83102 and `TOUCHSCREEN_SINTRONIX_TS` (S1, lines 346-352). Linux event-input backend exists (R2). | Selected driver can expose touch events to Rockbox. | Which controller binds on this board, firmware, coordinates, multitouch mapping, calibration, wake and suspend. Multiple configured drivers are not multiple verified chips. |
| Physical buttons | GPIO keyboard config (S1, line 341); generic Rockbox event handling (R2). | Map Linux input events for playback, navigation, volume and power. | Actual key controller, event codes, polarity/debounce, long-press and wake/shutdown semantics. No pin mapping established. |
| Internal storage | Observed dynamic `super` and boot-related partition names (D1). Source MMC plus UFS options (S1). | Linux host storage can serve a standalone root filesystem/library. | Actual storage medium/controller, full GPT, geometry, encryption implications, mount layout and robust recovery. Enabled UFS is not evidence of UFS hardware. |
| microSD | MMC/SDHCI MSM support enabled (S1, lines 491-498); hosted Rockbox mount model exists (R1). | Linux supplies block/filesystem access. | Slot wiring, detection and power, supported filesystems, hotplug and resume behavior. No custom reads/writes tested. |
| FLAC / Opus | Both codec sources included in official Rockbox (R3). | Rockbox can decode into the eventual verified PCM route. | Target build, codec ABI/loading, sustained playback and CPU/power cost. Source existence alone is not device playback. |
| Wired audio / S-Master HX | Sony specifies S-Master HX (P4). Open CXD3778GF control and Bengal MI2S links exist (S2-S4). | Reuse the Linux ASoC route and codec driver. | Active frontend/card/backend, board binding, clocks, DSP firmware/calibration and headphone output measurements. **Blocking for playback.** |
| PCM rate / depth / DSD | Codec DAIs declare S16/S24/S32, rates including 44.1/48 families through 352.8/384 kHz and DSD formats on selected DAIs (S4). | Some declared formats may be usable through a standalone route. | Actual negotiated/physical rates, DSP resampling, meaningful precision and target capabilities. No bit-perfect or native-DSD claim. |
| Volume / mute / jack | Table-based volume writes, mute controls, jack GPIOs and privileged table loading exist (S4-S6). | Independent initialization can replace Sony Android control services if all inputs are known. | Correct volume/calibration tables and permitted use, dB mapping, gain, jack debounce, mute/power ordering and bounded startup. Do not reuse guesses from NW-A30. |
| MD6000 / RME | Shared source enables an RME option and requests an external firmware payload (S1/S8). | This may be relevant to some product/path in the shared release. | Presence and role on NW-A306, whether required for PCM or DSD, payload provenance/licensing. Shared NW-ZX700 code is not NW-A306 hardware proof. |
| Sony effects | Stock features documented (P4); control hooks and optional processing interface exist (S4/S6); prior APK analysis preserved (D5). | Independently implemented Rockbox DSP can be evaluated separately. | Open implementations and licenses for Sony processing not established. DSEE/effect parity unproven. |
| SafeVolume / focus | Genuine timer activation, Sony focus request and Poweramp focus-loss pause preserved (D4). Earlier no-warning trials were inconclusive (D5). | That Android UI/service interaction need not exist in a standalone system. | Independent hearing-safety policy; no demonstrated suppression or hardware-limit bypass. No evidence that focus logs describe the codec path. |
| Battery gauge | Windows host displayed 97% (D3); QPNP_QG source config (S1, line 383). | Linux power-supply data can feed Rockbox monitoring. | Actual gauge and battery profile, units, accuracy, low-voltage cutoff and consistency across loads. Host percentage is not gauge validation. |
| Charging / USB power | QPNP_SMB5/SMBLITE and related charger options enabled (S1, lines 380-384). | Retain kernel charging and necessary policy under minimal Linux. | Board charger/PMIC, thermistor/profile/limits, USB negotiation, charge-while-off and safe fault handling independent of Android. |
| Suspend / wake / audio power | Codec early suspend/resume and GPIO/regulator control exist (S6); Qualcomm sleep infrastructure appears in related upstream SoC source (P5). | Linux plus retained platform firmware can manage power. | Wake sources, timers, DSP state, ongoing playback, storage/display resume, idle drain and charging interaction. No battery-life estimate justified. |
| Shutdown / watchdog | Qualcomm reset/watchdog configuration exists (S1); N1 reports NW-A30 shutdown limitations on a different system. | Privileged standalone init can coordinate a supported shutdown path. | NW-A306 PMIC shutdown/reset, watchdog ownership, storage flush and charging/reboot behavior. NW-A30 behavior cannot establish this. |
| Thermal / performance | Thermal/TSENS, CPU/devfreq and user-space thermal governor options enabled (S1, lines 385-401). | Kernel protection plus explicit userspace policy can replace Android responsibilities. | Board sensors/trips, policy/calibration, throttling and emergency shutdown. Removing Android policy without a replacement is unvalidated. |
| Bluetooth audio | Platform connectivity documented generically (P2); N1 reports Bluetooth unsupported in its unrelated port. | Linux host stack and a new Rockbox output integration may be possible. | Actual controller/transport/firmware, pairing, profiles, codec rights, encoder and routing/latency/power. No custom Bluetooth support established. |
| Wi-Fi / optional networking | QCS2290 platform offers connectivity (P2), not a board driver match. | Omit from initial standalone environment; investigate later if needed. | Controller, firmware, regulatory data, drivers, licensing and power behavior. No verified network configuration or telemetry assessment. |
| USB data / recovery | Historical ADB/fastboot accessibility reported (D2), not exercised in M0. | A standalone system may provide file transfer and diagnostics. | Gadget configuration, safe storage ownership, recovery reachability after boot failure; no supported EDL/programmer established. |

This matrix is a research backlog, not a compatibility list. Promote a row to
custom-firmware support only with a recorded test on identified hardware and
software, reproducible steps, actual results and relevant failure conditions.
